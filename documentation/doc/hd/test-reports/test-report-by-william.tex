\section{Test Execution}\label{sec:hd-testreport-execution}
The manual test cases defined in the \tradesq{} Front-End Test Plan were executed against the \tradesq{} Mobile Application running through Expo on a Oneplus 11. The application was connected to the self-hosted \tradesq{} Back-end API at \texttt{https://api.mufasadev.nl}.

Testing used a primary regular account registered through the application's registration flow. A second independent regular account was used where a test case required a listing owner, messaging counterpart, or target account for a permission-related check. The configured admin account was used for the admin-gated listing-management test cases.

The test cases were executed manually. For each case, the tester prepared the required pre-conditions, completed the planned steps, compared the observed behaviour with the expected result in the test plan, and recorded the outcome in this report. Where relevant, device settings and network connectivity were changed to test accessibility, session restoration, error handling, local drafts, and offline behaviour.

\section{Findings and Deviations}\label{sec:hd-testreport-findings}

This section records findings and deviations identified during execution of the \tradesq{} Front-End Test Plan. A finding is recorded when observed behaviour differs from the expected result, when a test case cannot be completed because of an environment or implementation issue, or when an important limitation is identified during testing.

No findings or deviations were identified during test execution. All 32 planned test cases were completed successfully and recorded as Passed.

\newpage
\section{Conclusion}\label{sec:hd-testreport-conclusion}

All 32 manual test cases defined in the \tradesq{} Front-End Test Plan were executed. All 32 test cases Passed; no test cases Failed, were Blocked, or were recorded as Not run.

The executed test cases verified the core front-end behaviour of the \tradesq{} Mobile Application, including registration and sign-in, authenticated-session restoration and sign-out, profile management, listing creation and management, search and filtering, favourites, messaging, notifications, image upload, protected-route handling, accessibility behaviour, text scaling, loading and error states, local listing drafts, and offline cached listing data.

No deviations from the expected behaviour were identified during the reported manual test execution. The results provide evidence that the \tradesq{} Mobile Application satisfies the front-end functional requirements and selected non-functional requirements covered by the test plan in the documented test environment.
