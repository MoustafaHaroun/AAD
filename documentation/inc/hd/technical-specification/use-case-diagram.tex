\section{Use Case Diagram}\label{sec:hd-use-case-diagram}
To simplify the use case diagram, the functional requirements from \cref{sec:hd-functional-requirements} are grouped under a category: \textbf{Account}: FR1, FR2. \textbf{Listings}: FR3, FR4, FR5, FR7, FR10. \textbf{Interest \& Favorites}: FR6, FR8. \textbf{Messaging}: FR9. \textbf{Media}: FR11. \textbf{Notifications}: FR12.

A single \textit{User} actor is defined for the mobile app -- the backend documents do not distinguish separate front-end actors (e.g. an admin-only UI), only backend requirements NFR8 for admin notifications, which are out of scope for the mobile app.
