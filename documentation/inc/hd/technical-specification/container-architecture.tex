\subsection{Container Architecture (C2)}
\label{sec:c2}

The C2 container diagram provides a higher-level technical view of the \tradesq{} Mobile Application.
It decomposes the application into its main runtime and local data-storage containers.
A container represents an independently executable application or a data store with a distinct responsibility.
In this context, a container does not refer to a Docker container.

\begin{figure}[H]
    \centering
    \includegraphics[width=\textwidth]{hd/diagrams/c2}
    \caption{C2 Container diagram of the \tradesq{} Mobile Application.}
    \label{fig:c2}
\end{figure}

As shown in \cref{fig:c2}, the \tradesq{} Mobile Application consists of the Expo React Native Application, Secure Session Storage, and Local Cache and Draft Storage.
The \tradesq{} Back-end API and the mobile operating system remain external systems because their internal implementation is outside the scope of this document.

\subsubsection{Expo React Native Application}
\label{sec:c2-expo-application}

The Expo React Native Application is the primary runtime container of \tradesq{}.
It is implemented in TypeScript using React Native and Expo.
It provides the application screens, Stack and tab navigation, reusable user-interface components, client-side validation, feature state, and communication with external services.

The application communicates with the \tradesq{} Back-end API through HTTPS.
It retrieves and updates shared application data, including authentication, profiles, trade listings, favourites, listing-interest events, notifications, and image-related data.
The application uses mobile operating-system capabilities through Expo and React Native platform APIs.

\subsubsection{Secure Session Storage}
\label{sec:c2-secure-storage}

Secure Session Storage persists authentication tokens and other small sensitive session values on the device.
The application uses \texttt{expo-secure-store} for this purpose.
Expo SecureStore provides encrypted platform-backed key-value storage through iOS Keychain services and Android Keystore-backed storage.

The Expo React Native Application stores and retrieves session information through this container.
Secure Session Storage is separate from the local cache and draft storage because authentication tokens and other credentials must not be stored with non-sensitive application data.

\subsubsection{Local Cache and Draft Storage}
\label{sec:c2-local-storage}

Local Cache and Draft Storage persists non-sensitive application data on the device.
The application uses Expo SQLite as its local database and Drizzle ORM to define the schema and perform typed database operations.

This container stores cached listing data, listing details, user preferences, and incomplete form drafts.
The Expo React Native Application reads and writes this data through local persistence adapters.
Authentication tokens and other sensitive session values are stored separately in Secure Session Storage.
