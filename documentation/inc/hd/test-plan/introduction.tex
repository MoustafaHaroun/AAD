\section{Introduction}\label{sec:hd-testplan-introduction}
This document describes the test plan for the front-end of \tradesq{}, the mobile application developed as part of the Hybrid Development course.
It defines manual test cases that verify the front-end functional requirements and selected non-functional requirements defined in the \emph{Requirements} section of the Technical Specification. 

The front-end currently has no automated test suite: no unit, component, or end-to-end tests are configured in the Expo project.
This document therefore defines a \emph{manual functional} test plan.
Each test case is executed by hand against a running instance of the \tradesq{} Mobile Application and the \tradesq{} Back-end API rather than by a test runner.
The cases primarily assess user-facing mobile-app behaviour.
Where a requirement can only be meaningfully verified through direct interaction with the \tradesq{} Back-end API, such as confirming a permission check that the mobile interface does not expose directly, the relevant test case states this explicitly.

The test cases are derived from the front-end functional requirements and selected non-functional requirements defined in the Technical Specification.
Requirements that need source-code inspection, release-process evidence, specialist security assessment, or automated-test evidence are outside the scope of this manual test plan.
