\section{Approach}\label{sec:hd-testplan-approach}

\subsection{Test Environment}\label{sec:hd-testplan-environment}
A tester should execute the test cases against a running instance of the \tradesq{} Mobile Application connected to an available instance of the \tradesq{} Back-end API.
The tester should use a physical Android or iOS device where possible, because several test cases require device capabilities or system settings, including image selection, network connectivity changes, screen-reader navigation, and system text scaling.

Before test execution, the tester should prepare a primary regular test account and, where applicable, an admin account.
The tester should also prepare a second independent regular account for test cases that require a listing owner, messaging counterpart, or target account for permission-related checks.

\end{htable}

The test report should record the actual application version, device model, operating-system version, \tradesq{} Back-end API instance, test date, and any deviations from this planned environment.

\subsection{Result Scale}\label{sec:hd-testplan-result-scale}

When executing a test case, the tester should assign one of the following results.
The completed results and any supporting evidence should be recorded in the separate test report.

\begin{htable}[
    caption = {Result Scale},
    label = {tab:hd-testplan-result-scale},
    presep = 1em,
]
    {
        colspec = {lX},
    }
        Result & Meaning \\
        Passed & The application behaves as described in the test case's expected result. \\
        Failed & The application does not behave as described in the test case's expected result. \\
        Blocked & The test case cannot be completed because a prerequisite fails or the required test environment or data is unavailable. \\
        Not run & The test case has not yet been executed. \\
\end{htable}
