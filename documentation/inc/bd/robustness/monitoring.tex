\section{Monitoring}\label{sec:monitoring}

\subsection{Overview}
Administrators need to be able to observe the health of the system at a glance and be alerted about problems. The monitoring stack runs as a separate Docker Compose application alongside the backend. It consists of three services: Prometheus for collecting metrics, Loki for aggregating logs, and Grafana for visualisation. The Grafana dashboard is fully pre-provisioned, meaning it requires no manual configuration after deployment.

\subsection{Prometheus --- Metrics Collection}
Prometheus scrapes the \texttt{/metrics} endpoint of the NestJS application every 5 seconds. The application exposes metrics using the \texttt{@willsoto/nestjs-prometheus} package backed by \texttt{prom-client}.

Two custom metrics are recorded by the \texttt{HttpMetricsInterceptor}, a NestJS interceptor that wraps every incoming HTTP request:

\begin{htable}[
    caption = {Custom Prometheus metrics},
    label = {tab:metrics},
]{
    colspec={llX},
}
    Metric & Type & Labels \\
    \texttt{http\_requests\_total} & Counter & method, path, status \\
    \texttt{http\_request\_duration\_seconds} & Histogram & method, path, status \\
\end{htable}

In addition, \texttt{prom-client} automatically collects standard Node.js runtime metrics, including heap memory usage, active handles, garbage collection duration, and event loop lag.

\subsection{Grafana Dashboard}
The dashboard is provisioned automatically from files in \texttt{monitor/grafana/provisioning/}. It contains ten panels divided between Prometheus metrics and Loki log streams.

\begin{htable}[
    caption = {Grafana dashboard panels},

]{

}
    Panel & Source & Description \\
    Request Rate & Prometheus & Requests per second grouped by method and path \\
    Error Rate 4xx & Prometheus & Rate of client errors over time \\
    Error Rate 5xx & Prometheus & Rate of server errors over time \\
    Request Duration p50/p95/p99 & Prometheus & Latency percentiles for all endpoints \\

\subsection{Verifying the Monitoring Setup}
The Prometheus targets page at \texttt{/targets} shows the scrape status of every configured job. The \texttt{trade2-nestjs} job must show \textbf{State: UP} for metrics to be collected. Running the following query in Grafana Explore confirms that the target is reachable:

\begin{longlisting}[caption={PromQL query to verify scrape health}, label={lst:prom-up}]
up{job="trade2-nestjs"}
\end{longlisting}

A result of \texttt{1} confirms that Prometheus is successfully scraping the application.
